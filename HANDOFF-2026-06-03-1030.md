## What was wrong and what fixed it (all merged)

### PR #1 — `7eb943f` "repair all napGPT UI workflows"
The original daily failure emails + latent issues:
- **a11y contrast** — `EffortBar` effort-hint span used `opacity-60`, compositing to 4.11:1
  (< WCAG AA 4.5:1). This failed the nightly a11y budget gate every night. Fixed:
  `opacity-80` (~7.6:1). `src/components/EffortBar.tsx`.
- **UI MCP Tests red since March** — `ui-mcp.yml` built **without** `NEXT_PUBLIC_TEST_MODE=1`,
  so `window.__nap_store` wasn't exposed and timers ran real-time → beans/energy/boost/drift
  scenarios failed. Fixed: added the flag to the build step (8/14 → 14/14).
- **UI Tests 6h hang ×4 jobs** — `jest --runInBand` under `jest-puppeteer` never exited.
  Two-part: (a) `--forceExit` on `test:ui-all`; (b) the real cause was a **port conflict** —
  the workflow starts the app on :3000 and jest-puppeteer's `server` block tried a 2nd
  `npm run start` on the same port, and `jest-dev-server`'s default `ask` action blocked on
  stdin in CI. Fixed with `usedPortAction: 'ignore'` in `jest-puppeteer.config.js`.
  Added `timeout-minutes` guards to all jobs in `ui-tests.yml`.
- **Full Suite headful exit 127** — `xvfb-run --auto-servernum HEADFUL=1 npm ...` made
  xvfb-run run `HEADFUL=1` as a program. Fixed: env var before `xvfb-run` in `ui-all.yml`.
- **Cross-spec state bleed** — jest shares one page; app persists chat history to
  localStorage, so a message from `a11y.spec` leaked into `chat.e2e` (flaky by file order).
  Fixed: global `beforeEach` clears storage in `jest.setup.ts`.

### PR #2 — `4100bed` "Revive toast + bump CI actions to Node 24"
- **Boost-refused toast revived** — `EffortBar` disabled the Boost button at 0 beans, so
  `handleBoost`'s "Not enough coffee beans" toast was dead code since the initial commit.
  Removed `beans === 0` from the disabled condition; rewrote scenario 36 to assert the toast
  fires. (Earlier in the session the user first chose "fix the test"; then chose to revive
  the feature — current state is **revived**.)
- **Node 24 actions** — `checkout`/`setup-node`/`upload-artifact` → `@v6` across all 3
  workflows (Node 20 was being force-migrated). `upload-artifact@v6` is the first version
  that runs Node 24 by default with no functional change.

### PR #3 — `a6bb7a9` "Harden flaky 96_wake_reactions"
- After a11y was fixed, the nightly stopped failing deterministically but **flaked** — and
  the single cause of BOTH the headful and live-LLM job flakes was `96_wake_reactions`. It
  required the reply to contain words like "up/here/ready", which neither a random mock nor
  a real LLM reliably emits. Fixed: `MockLLM` now returns a deterministic wake-themed reply
  for greeting/wake words; scenario 96 asserts **responsiveness** (every keyword gets a
  substantive reply) — mode-agnostic — with wake phrasing kept as informational signal.
  `src/lib/llm/mock.ts`, `scripts/mcp/scenarios/96_wake_reactions.ts`.

## Key facts for the next session

- Mock vs real LLM in CI: the app uses `MockLLM` when no `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`
  is set. Locally there's a gitignored `.env` with a key, so to reproduce CI's mock mode run
  with `ANTHROPIC_API_KEY="" OPENAI_API_KEY="" LLM_API_KEY=""`. Confirm via `/api/mode` → `{"isMock":true}`.
- `window.__nap_store` and fast test timers only exist when built with `NEXT_PUBLIC_TEST_MODE=1`.
- Repro a CI run locally: `NEXT_PUBLIC_TEST_MODE=1 npm run build` → start app with the empty
  keys above on PORT=3000 → `npm run test:mcp` (14 scenarios) or `npm run test:ui:headful`
  (extended Full Suite) or `CI=true npm run test:ui-all` (jest specs).
- `a11y.spec` allowlists `color-contrast` only when `CI=true` (animation-compositing artifact);
  locally without `CI=true` it will flag it — set `CI=true` to match CI.
